# Development guide

Wilderness Almanac uses vanilla JavaScript ES modules, Vite and Three.js. World generation and numeric geometry are independent of the DOM and renderer. Campaigns and palettes use browser IndexedDB. An optional self-hosted Node/SQLite API provides authenticated campaign copies, with Cloudflare Pages serving the frontend and proxying API requests. There is no runtime connection to the source spreadsheet. See [SELF_HOSTING.md](SELF_HOSTING.md) for authentication, deployment, migrations, backups and restore instructions.

Read [PROJECT_STATE.md](PROJECT_STATE.md) for generation and visual constraints, and [AGENTS.md](../AGENTS.md) for repository working instructions.

## Setup and checks

Use Node.js 24 or later (`.nvmrc` selects 24):

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run format:check
npx playwright install chromium
npm run test:e2e
```

`npm test` runs the Node test suite. Prefer focused checks for the affected behaviour; reserve full suites and builds for explicit requests or substantial risk, once changes settle. Use `npx prettier --write <changed-files>` to format touched files. `npm run preview` serves the production build. `npm run check` runs formatting, unit tests, a production build and browser tests in order. The browser tests serve the built app on port 4178; build before running `npm run test:e2e` on its own.

The optional backend has a separate lockfile: `npm ci --prefix server`, then `npm run test:server`. `npm run test:account` exercises only the account dialog against a local source server with mocked HTTP responses. Account/storage browser checks use their own configurations and are excluded from the renderer suite. Frontend-only `npm ci` and `npm test` do not require backend dependencies. The manually dispatched CI workflow also runs the backend and account checks.

The Playwright suite in `e2e/` runs against Chromium at desktop and phone viewports. It covers campaign replacement/zoom, edit-preserving JSON import/export, dirty-form navigation, Undo, save failure/retry/recovery and mobile panels. Renderer checks also cover pan, zoom limits, keyboard focus, reduced-motion changes and emulated two-finger pinch. Each test uses an isolated browser context and deterministic campaign fixture; simulated storage failures are confined to test initialization. One worker bounds software-WebGL CPU/memory use, with a 20-minute suite limit inside the 25-minute CI job. Browser tests wait for map actions to clear the workspace’s busy state before reading saved results. Failure screenshots, traces and an HTML report are written under ignored `test-results/` and `playwright-report/`.

Automatic push and pull-request runs in `.github/workflows/checks.yml` are temporarily paused. Manual dispatch remains available and runs formatting, unit tests, the build and desktop browser tests with Node 24. Restore the push/pull-request triggers when automatic checks are ready to resume. Mobile map browser tests are temporarily paused in CI because their helpers assume visible multi-edit controls and an open Inspector; repeated waits exhausted the suite timeout. Re-enable them after the helpers handle the mobile disclosure and navigation states reliably. Both map browser projects remain available locally through `npm run test:e2e`; use `-- --project=mobile` for mobile only. Official actions are pinned to commit SHAs, the job uses read-only repository permissions and uploads browser reports for seven days.

Inspect visual changes in a real browser at desktop and phone widths. Check map selection, tool panels, viewport expansion and browser errors when changing workspace layout. Pointer-driven mobile emulation does not establish physical touch/pinch correctness.

## Fog of War

See [FOG_OF_WAR.md](FOG_OF_WAR.md) for sight and water rules, masked display data, material variants, campaign persistence, editing restrictions and focused verification. Inland high points add elevation minus one to first-water reach above level 1, with equal/higher terrain blocking that extra view. `canSee` retains the ordinary sight path and applies the additional path only to open-water targets; source candidate filtering includes this longer reach without extending land visibility. Coastal sources, ordinary far shores and island stops retain their existing rules. Keep visibility independent of generation and use the same projection for map geometry, labels, proximity searches and Inspector previews.

## Generation and rendering boundary

```js
import { generateWorld, generateDressing } from './src/generation.js';
import { prepareMap } from './src/generation/presentation.js';

const world = generateWorld('the-same-seed');
const dressing = generateDressing(world, 0);
const renderData = prepareMap(world, dressing);
```

These three results are plain data. Run the example from a module at the repository root. `generateWorld` owns geography and feature placement; `generateDressing` owns cosmetic variants; `prepareMap` builds numeric mesh descriptors without mutating the world. Campaign edits are resolved over the generated base by `campaignWorld` and `campaignDressing`.

Use named random streams so changes to one stage do not consume another stage's randomness. Keep seed replay and JSON compatibility deliberate. A change to world-generation rules, vocabulary or naming modifiers requires a generator-version decision and a corresponding snapshot update when applicable. Pure refactors should preserve generated data, dressing and geometry exactly. Cosmetic changes must respect saved dressing snapshots and locks.

Renderer tests in `tests/rendering.test.js` compare seeded mesh buffers, transforms, materials, wind attributes and picking ranges against pre-refactor fixtures in `tests/fixtures/rendering.json`, and verify geometry/material disposal. Treat intentional visual changes as explicit fixture updates; do not regenerate these fixtures merely to make a failing test pass.

Village cottages lower only their straw-roof wall height by 15%; roof dimensions and town/city models are unchanged. Village fence eligibility uses the existing independent dressing stream at 60%, retaining all clearance and mountain restrictions. Watchtower battlements and banners use the shared POI material/batching path and reserved footprint. Thumbnail cache version 6 invalidates previews for the current terrain dressing.

Current version-9 terrain dressing uses `generation/mountain-ridges.js` for a deterministic main crest and branch network, with coherent height/width variation sampled by `ridge-surface.js`. Mountain locks include optional `profile: 0 | 1`; an older lock without a profile selects the legacy field, so existing foundations and shared seams remain intact. Cosmetic changes do not advance the world generator: topology, elevations, settlements, POIs and road routes are unchanged. Versions 6–8 retain their original mountain and farmland dressing.

`crops` descriptors carry an optional `cropStyle` enum (plots, grain or vineyard), and farmland trees carry an optional boolean `fruit`; import validation bounds both and requires fruit-bearing trees to have a deciduous crown. `generation/grain-fields.js` partitions the usable hex into broad irregular patches, subtracting bounded road/POI/tree/token reservations and merging adjacent pieces where their union stays convex. New grain descriptors store at most 24 counterclockwise convex outline points; imports validate point count, area, winding, finite coordinates, declared footprint and tile fit, never accepting imported triangle meshes. At most 24 patches occupy a tile. `generation/farmland-patches.js` supplies pure local relief, outline distance and dense staggered stalk sampling. The grain builder subdivides the golden ground to follow that relief and any existing road ramps. Ground stays stationary; crossed stalk/head geometry uses the existing paused wind clock and material batches. Older locked grain descriptors without outlines keep the previous rectangular model. Vineyard and fruit geometry use shared palette materials, batching, picking and disposal. Vineyard labels derive from actual dressed props, including locks, while the editable terrain remains Farmlands. Fruit colour selection compares red, orange, yellow, green and purple candidates against both leaf shades, including neutral custom palettes.

The renderer entry coordinates scene lighting and the public `setMap`/`setPalette`/selection/zoom/motion/snapshot/disposal API. Arrow-key panning uses the renderer’s `pan` action to move the camera along the ground plane by two hex-centre spacings per key press, independent of zoom. Held-key repeats, active drag/pinch gestures, busy actions, editable controls and open dialogs do not pan. Camera height, angle, zoom, selection and party position stay unchanged. `map-meshes.js` owns map geometry and batches props by material/shadow role while retaining face ranges for hex picking. Terrain/river meshes, natural props and crossings have focused builders alongside settlements and POIs. `map-materials.js` owns shared/tinted materials, shader uniforms and depth materials; map rebuilds release geometry while retaining these materials. `map-controls.js` owns the camera, selection rings, picking, pointer/wheel listeners and resize observer. Touch zoom supports pinch and a nearby second press within 300 ms of a short tap: hold that press and slide down to zoom in or up to zoom out, using the existing zoom bounds. Short map taps wait for that window before selection so zoom cannot trigger party destination confirmation or toggle multiselect. Sliding suppresses selection and long-press; a second finger switches to pinch. Cancellation, navigation and disposal clear pending taps and gesture state. `ambient-motion.js` owns motion scheduling and reduced-motion/visibility listeners. Disposal stops motion and releases controls, map geometry, materials and scene resources through their respective owners. The menu and Inspector share one still preview renderer; avoid adding animated scenes or per-hex WebGL contexts. Inspector previews opt into camera-space fitting of all rendered vertices, including raised tile bases and tall props, with 8% framing padding. Their images fit the square frame at 100% without additional CSS enlargement. Campaign-card icons retain the original fixed framing and thumbnail cache. Three.js is intentionally pinned to `0.160.1`.

The Hex Inspector orders its metadata as Terrain, Elevation, Settlement, Point of interest, Crossing and Road exits. Read mode pairs Crossing with comma-separated road exits; edit mode puts road checkboxes on a full-width row. `ui/poi-options.js` supplies shared single/batch choices, combining named subtypes into labels such as Mystic · Portal. Numeric POI variants have one choice per kind and remain cosmetic: local hex revisions cycle their rendered model and detail seed through independent deterministic streams in `generation/props.js`, leaving the seeded world feature unchanged. Existing unrerolled models retain their original descriptors. Named subtypes remain fixed through regeneration. Watchtower detail seeds also reroll locally to choose a roofed or battlemented model with a banner, while the Watchtower/Lighthouse semantic variant remains unchanged. Unchanged single edits and same-kind numeric batch choices preserve the existing POI identity; frozen dressing validates numeric cosmetic variants independently of the world variant, while named subtype matches remain exact.

`campaign-session.js` owns the active record, base/effective world, dressing, selection and a maximum of 20 undo entries. Actions derive/validate the next state before committing it, then call an injected persistence adapter. Results distinguish world, tracking and palette updates and retain separate campaign/preferences save outcomes. A failed save keeps live changes and history; the DOM handles warnings rather than rolling back an applied action. Palette changes survive hex Undo, and opening/replacing a world resets history.

Party markers store the optional validated `partyToken: { key, style }` record in campaign saves/exports. `application/party-token.js` validates the fixed-footprint key and `cairn`/`warden`/`waystone` style. Campaign entry initializes missing tokens as Warden on the settlement nearest axial origin, with dry-land then any-hex fallbacks, and marks the starting hex visited without an Undo entry. Existing token positions and manually changed visited flags survive entry. Placement commits token position and the destination's existing visited flag together as a tracking action, sharing world/dressing, with one save and one Undo entry. Undo restores the old position and visited state while preserving a later style choice. New Map initializes a fresh token.

`rendering/party-piece.js` builds the three meshes; `party-color.js` preserves the prototype's red/cyan/lime OKLab separation heuristic. `party-token.js` owns the overlay scene, terrain-height placement, marker selection, reduced-motion-aware drop/lean and finite animation scheduling. A click keeps the base grounded and nudges the piece toward camera-right, rebounds one fifth as far left, then settles; only a drag release triggers the drop. It uses the map camera without changing it and clears depth before drawing the piece so props cannot obscure it. Preview renderers never create a party controller. Map controls route marker gestures separately from map pan/selection: clicking the piece selects its base highlight only; clicking exposed terrain on its hex still selects that hex. Pointer cancellation and invalid releases return the marker to its saved position. Visited state produces no map marks. Sandbox Tools stays empty; no movement controls are added to Sandbox tools. Party movement shortcuts and instructions belong to Party Inspector and the map overlay. The Inspector movement hint shares the metadata heading column and pin gutter, aligning its text with the metadata labels on desktop and mobile. `party-inspector.js` replaces the hex/batch Inspector while the ephemeral session party selection is active. Token and hex selections are mutually exclusive; the retained primary hex is only an internal return target. Switching from a dirty hex/batch form uses its existing draft guard. The shared still renderer fits a standalone token mesh for the portrait without adding another WebGL context. Clicking, tapping or keyboard-activating the portrait explicitly reveals the local colour-swatch and person icons, keeping aria-expanded consistent with visibility; colour cycles red/cyan/lime from the current adaptive colour and person cycles the three types. Explicit colour overrides, trimmed party name (1-100 characters), and optional positive integer weeks survive validation, saves and exports. Missing names show Adventurers and missing weeks show 1. Legacy daysTravelled/sessionsPlayed remain validated and preserved in backups, independently of the new weeks field. The name field shares the campaign-name pencil pattern, saving on change/submit and reverting on Escape or a blank edit. The portrait, name, coordinates and metadata share one overview without a separate section heading. A compact portrait leaves room for metadata rows with fixed pin, label and value columns. Metadata uses a 1.25 line height, a 12px gap after coordinates and uniform rows separated by 4px, including rows without pins. Metadata pins align with the coordinates pin; Weeks travelled reserves the same empty pin column so their labels align with coordinate text. The portrait stays beside one heading column containing the name, coordinates and all metadata, including on mobile. Fine-pointer pins use compact 20px targets, while coarse pointers retain the shared touch target size. Name and appearance changes save without entering hex Undo history. A local compass button beside coordinates and map-pin buttons beside nearest settlement/POI values select the exact target hex and explicitly centre/zoom the map (retaining an already closer view); ordinary token placement still leaves the camera unchanged. The selection dropdown lists the party first by its saved name and selects it while Party Inspector is active. The header’s Find party action uses the same draft guard, selects the party and calls camera focus three standard zoom-in steps closer than a nine-hex horizontal span (9 / 1.2³, roughly five hexes across). Its miniature reuses the shared still renderer and refreshes only when token style, colour or palette changes; the bundled user icon is the fallback. Inspector pins retain their closer-view focus behaviour. Drag-and-drop placement works on desktop and mobile with fog on or off. On mobile only, tapping the party’s current hex selects that hex immediately; tapping a different hex while the party is selected opens a named destination confirmation in either fog mode; Cancel and Escape preserve the token position, deselect the party and select the clicked hex. Pointer clicks on modal buttons require a fresh pointerdown on that button after opening, preventing the opening map tap from also confirming or cancelling the dialog; keyboard and assistive activation remain available. Opening or resolving the dialog cancels map/token pointer gestures, and resolving it clears the pending destination synchronously. Drag callbacks cannot move a deselected party or move it while the dialog is open. Move token uses the existing visited/save/Undo action. Dropdown hex choices and Inspector pins still navigate directly. The Party Inspector aligns every metadata pin and label with its location row beside the portrait. The visited grid button replaces selection with the counted visited land hexes in multi-edit, without moving the camera, saving or adding Undo history. Missing targets and an empty visited set disable their pins; weeks have none. Metadata measures axial distance to any settlement footprint (including the current settlement at zero) and to the nearest POI, using its name or existing type/variant label. Coverage counts visited non-open-water hexes divided by all non-open-water hexes, including river-bank tiles and excluding ocean/lake/open-water terrain; an empty denominator yields 0%. Party Inspector rows size to their content, leaving remaining desktop space to Sandbox Tools when it is open. Returning to hex selection restores the ordinary panel layout and heading.

Multi edit keeps an ephemeral selection set in the session, alongside the primary inspected hex. `panels.setMultiEdit` temporarily forces Sandbox tools closed and disables its expansion button, preserving its preferred collapse state and vertical rail. Reordering and switching between rail and panel remain available. Leaving multi-edit restores the preferred collapse state; the temporary restriction is not saved. Opening/replacing a campaign resets the mode; selection changes do not save or enter history. `batch-inspector.js` sends only explicitly chosen fields. `applyBatch` normalizes terrain-dependent removals, merges all target edits through `updateHexes`, derives the final world/dressing once and validates crossings for every target before one commit/save/Undo entry. Shared snapshot invalidation examines the union of affected components before and after the complete batch. Structurally edited locked hexes are relocked with their new dressing; tracking-only batches share the existing world/dressing. Renderer selection highlights are a disposable combined ring mesh; map refresh and silent programmatic selection never toggle batch membership.

`settlement-edits.js` validates connected, same-type town/city selections and assigns a bounded group identity. Join affects exactly the selected tiles, repairs remaining footprints and retains one Undo/save boundary. Village footprints always split into individual cells. Joined records use edit-state version 2 with a validated `settlementGroup`; version-1 records remain accepted. Changing settlement type removes group membership. `map-action.js` uses the menu's two-frame paint delay, busy animation and control disabling for Apply, Join, Select all, Clear selection, Undo, Reset and Regenerate; selection changes are blocked while pending. Selection actions pass their activating buttons through draft protection, so Selecting… and Clearing… paint before highlight geometry is rebuilt. Field errors use a shared red tint and `hexAddress` includes region plus local coordinates.

Ctrl+click or Cmd+click on the campaign map enables multi-edit through the same dirty-draft guard as the Hex Inspector’s Multiselect button. Cmd+click supports macOS, where Control-click opens the system context menu. The inspected hex stays selected and a different clicked hex is added; clicking that same inspected hex when enabling keeps it selected. Pointer modifiers travel through renderer selection callbacks and deferred draft actions. Once multiselect is on, plain clicks/taps and Ctrl/Cmd-clicks all toggle membership without clearing the other selected hexes. Ordinary clicks in single-hex mode still inspect one hex. A 550 ms touch hold on an unselected hex adds it to the current selection and enables multi-edit through the same draft guard. Movement of six pixels, a second pointer, cancellation or disposal cancels the hold; its release never repeats selection. The coordinate selector explicitly requests additive selection while multi-edit is active. Turn off multiselect beside Clear selection uses the same guarded mode change and grid-2x2-2 icon as Multiselect. The Hex Inspector’s first action row holds Edit, Multiselect, Reset and Regenerate. Edit is the gold primary action; Undo appears only during single-hex editing, supports committed history when the draft is unchanged and disables for dirty drafts. Lock appearance and Use as campaign icon occupy the second row. During Edit, both rows become one wrapping action cluster, including Undo; every action retains the shared control height. Multiselect uses the grid-2x2-2 icon and remains available in either fog mode. The desktop top toolbar holds the fog switch; responsive layout moves that same control into the mobile map stage’s top-right corner so it remains available in expanded view. The expanded desktop appearance panel stacks Time, Regenerate and Movement beside the palette picker. Mobile retains the same compact swatches, picker, Time and disclosure in either state. Opening appearance adds a row below: Movement shares the picker column, while Regenerate spans the Time and disclosure columns. The map panel grows by that row’s height, pushing the tools down without shrinking the map. New Map and its replacement dialogs are no longer exposed in the campaign workspace. Drag/pinch and creation-preview selection retain their existing behaviour.

Reset selected requires confirmation and removes the selected sparse edit records through null patches in `updateHexes`. Structural removals invalidate affected shared snapshots before rebuilding once. The reset clears selected tracking, locks, local dressing and settlement groups, with one save/Undo entry; seed, palette, global dressing variant and selection remain unchanged. Its confirmation discards selected draft changes directly, without a second draft dialog, and uses the same working indicator as Apply.

The homepage statically imports no renderer or Three.js code. `src/ui/map-view.js` is dynamically imported on campaign entry and shares the still preview renderer with Inspector. Campaign creation/entry immediately disables menu controls, marks the activating button busy and announces loading; feedback paints before synchronous generation or scene work. Errors restore menu controls without discarding saved campaigns. Missing WebGL is an entry failure with a retryable menu message. Navigation requests queue through active transitions, and skipped/aborted transition animations still commit the prepared view. Directional native view transitions run after preparation: left into the workspace, right back to the library. Reduced motion and unsupported browsers switch immediately. Navigation restores menu scroll and focus and cleans up pending transitions on disposal. The campaign canvas keeps keyboard focus on entry, but its outline appears only after keyboard input; pointer/touch input clears that visual focus mode, preventing an automatic border around the map. Failed imports leave the menu usable; reload after a failed module fetch to retry. Keep renderer imports behind this boundary. The browser suite checks requests before/after entry and enforces a 200 KB uncompressed initial-JavaScript budget.

Campaign icons use a stable gallery of up to eight distinct hexes: four settlements followed by four POIs, with remaining landmarks filling shortfalls. Featureless worlds fall back to eligible terrain. After the map paints, still previews are captured one tile per task using the shared renderer. A manually selected Inspector hex is retained as an optional ninth entry, including meadow or water; further manual choices replace that extra entry. Menu refresh cycles only through ready cached entries, wrapping in order. It is disabled until at least two previews are ready, so it cannot select an unseen result. The menu never fetches a renderer.

A best-effort IndexedDB gallery cache and a session fallback each retain at most 32 campaign galleries (up to nine previews each). Each campaign occupies one stable record; new renders replace that record rather than consuming new cache slots. Signatures include campaign identity, cache/generator version, seed, world preferences, variant, palette and visual hex edits; icon choice, names and visited-only changes reuse previews. Cache failures do not affect campaign saves or JSON exports. Palette, dressing and structural edits rebuild stale previews after a short debounce; superseded jobs stop between tiles. The menu retains the last preview of the same hex/world during palette or dressing updates, and reuses card/image nodes to avoid flashing the fallback on navigation. Missing previews use the bundled meadow image, with fixed Dusk ground and Ember foliage. Road topology is generated by `generation/roads.js` after POIs/crossings. Each generated link retains its endpoints and graph path. Campaign edits filter these original links and persist removals; they never rerun generation or reallocate freed budget. Inspector exit edits use canonical undirected edges, update both visible hexes and remain outside the generated budget. `road-geometry.js` creates plain numeric curves, terrain-matched ramps and narrow prop reservations from independent cosmetic streams. Undiscovered fog tiles omit all road descriptors.

## Time of day lighting

`application/time-of-day.js` contains the Dawn/Day/Dusk/Night presentation presets and chronological cycling order. The appearance panel uses one cycling Time button with the bundled sun/moon Pixelarticons instead of a select. The optional validated campaign `timeOfDay` field survives local/account saves and JSON exports; missing fields default to Day when presented. New campaigns use the saved default time of day, initially Dawn. `campaign-session.setTimeOfDay` saves a presentation change without regenerating geometry or adding Undo history. `main.js` restores the button label/icon and renderer on every campaign entry. Fog retains its mobile map placement; Time moves between the palette-picker row and the desktop action stack without duplicating controls. Map replay, palette seeds, menu icons and still Inspector previews retain their existing behaviour; still previews always use Day.

`rendering/daylight.js` owns the hemisphere, directional sun and a soft, shadowless eastern dawn fill. Dawn uses the map compass east vector; dusk uses the lowest western sun for the longest shadows. Day retains the original light values, sun position and shadow frustum. Night disables sun shadows, reduces/desaturates material colours with a navy cast, and updates cached tints, fog materials and background without cumulative colour changes. The party overlay follows the same rig. Shared wind uniforms set Day sway strength to 1.2 and gust period to 18 seconds; dawn/dusk/night retain strength 1 and 24 seconds. Leaf, trunk, reed, tinted, fog and shadow materials share these uniforms, so time changes preserve matching silhouettes and shadows without rebuilding meshes.

Settlement/POI builders report local light anchors through an optional callback; `map-meshes.js` transforms them from the actual model matrices after fog projection and tags their settlement size or POI kind. `feature-lighting.js` retains a separate window and local ground pool for every building/feature, merged into six colour/layer batches. Warm pool intensity is 2.5 times the original setting, with modest population/landmark radius differences. Pools clip to their local footprint and the actual tile top triangles, including relief, road ramps and dry river banks; there is no settlement-wide blanket pool. Warm buildings stay out of the camera-centred native point-light pool, keeping their glows consistent across the viewport. Up to four shadowless point lights supplement mystic/dungeon sources; fogged sources emit nothing.

`feature-glow.js` derives stable phase/rate values from each emitter's position and tile key without consuming generation randomness. Per-vertex attributes preserve these values after batching; a shared shader clock pulses each emitter independently between 40% and 100%. Window and ground pools belonging to the same emitter stay matched. No extra per-building draw calls or lights are needed.

`lighthouse-beams.js` precomputes a continuous visible-water sweep up to 120 degrees wide and two hex-centre spacings long, shortening its reach/arc at land, fog and map boundaries. Shaft and round-landing clearance are checked along the route; the animation interpolates cached targets without searching the map each frame. A shared, subdivided cone fades along its final portion into a soft circular radial footprint restricted to nearby visible water triangles. Each lighthouse owns its shaft/landing materials and landing geometry; cone geometry and glow texture are shared. Two shadowless spotlights supplement nearby beams. Rebuild/disposal releases owned geometry and materials. Pulses and independent, slow sweeps use the existing 20-fps ambient clock, so Movement off, reduced motion and hidden-document handling freeze them without another animation loop.

Frozen road shapes store only variant/revision seeds; imported road meshes or curve arrays are never accepted. - Product namespaces use `wilderness-almanac` for packages, browser storage, exports, proxy headers and deployment defaults. ## Interface conventions

Styles follow CUBE CSS in ordered `reset`, `tokens`, `base`, `compositions`, `utilities`, `blocks` and `exceptions` layers. Use native nesting within blocks, `cluster`/`stack`/`grid-pair` for composition, and shared rem-based spacing, typography and control tokens. Keep state overrides in `exceptions`; reserve `!important` for the native `hidden` contract. Prefer labelled semantic HTML and remove wrappers when the parent can own the layout. Keep reusable UI structure in native `<template>` elements in `index.html`; clone with `src/ui/templates.js`, then populate text, attributes and options through DOM APIs. Preserve static icons when updating labels. Use .primary-button for primary actions so gold fill, hover colour, disabled state and shared press-scale/reduced-motion feedback stay consistent across menu dialogs and campaign tools; the campaign creator toggles this class between Generate preview and Create campaign as its draft changes. Desktop Inspector action groups share equal-width grid columns across read, edit and batch modes, with container queries adapting the column count.

Use Geist Sans for body copy and controls, and Geist Pixel Square for titles, metadata values, seeds and status details. Fonts are local and preloaded. Keep the render-blocking stylesheet and inline dark defaults in `index.html` so the initial paint does not flash white or unstyled content.

Set `overscroll-behavior-y: none` on `html` and `body` in the base layer and inline startup styles. This disables browser pull-to-refresh throughout the app in supporting browsers, including the menu and dialogs, while retaining ordinary scrolling, horizontal navigation and map gestures. Keep this global rule when changing page overflow or expanded-map layouts; local dialog/panel scroll containment remains separate.

Map-bearing layouts use stable small-viewport height (`svh`): the page minimum, campaign workspace, mobile map, expanded map and New campaign dialog/preview. Browser-bar show/hide animations must not resize the canvas or repeatedly trigger its resize observer. Small-viewport sizing keeps map controls and the collapsed tool headers visible with browser bars open; rotation and actual window resizing still update the layout. Keep `dvh` for non-map dialog maximum-height constraints.

The main-menu heading reads “The Wilderness Almanac” on three fixed lines, using a compact 2.5–3rem main font size. The article uses 50% of that size, approximately matching the width of the W below, with its own line height of 1 and proportional letter spacing. The main line height is 0.9; a −0.025em margin above Almanac tightens only the final line gap while retaining space between the glyphs. The main-menu browser title includes the same article.

At narrower desktop widths the library reserves the left margin for the frame; heading text still aligns with the campaign UI.
