# Development guide

Wilderness Almanac is a client-side application written in vanilla JavaScript ES modules, with Vite and Three.js. World generation and numeric geometry are independent of the DOM and renderer. There is no application server, database, account system or runtime connection to the source spreadsheet.

Read [PROJECT_STATE.md](PROJECT_STATE.md) for generation and visual constraints, and [AGENTS.md](../AGENTS.md) for repository working instructions.

## Setup and checks

Use Node.js 24 or later (`.nvmrc` selects 24):

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run format:check
npx playwright install chromium
npm run test:e2e
```

`npm test` runs the Node test suite. Prefer focused checks for the affected behaviour; reserve full suites and builds for explicit requests or substantial risk, once changes settle. Use `npx prettier --write <changed-files>` to format touched files. `npm run preview` serves the production build. `npm run check` runs formatting, unit tests, a production build and browser tests in order. The browser tests serve the built app on port 4178; build before running `npm run test:e2e` on its own.

The Playwright suite in `e2e/` runs against Chromium at desktop and phone viewports. It covers campaign replacement/zoom, edit-preserving JSON import/export, dirty-form navigation, Undo, save failure/retry/recovery and mobile panels. Renderer checks also cover pan, zoom limits, keyboard focus, reduced-motion changes and emulated two-finger pinch. Each test uses an isolated browser context and deterministic campaign fixture; simulated storage failures are confined to test initialization. One worker bounds software-WebGL CPU/memory use, with a 20-minute suite limit inside the 25-minute CI job. Browser tests wait for map actions to clear the workspace’s busy state before reading saved results. Failure screenshots, traces and an HTML report are written under ignored `test-results/` and `playwright-report/`.

`.github/workflows/checks.yml` runs formatting, unit tests, the build and desktop browser tests on pushes to `main`, pull requests and manual dispatch with Node 24. Mobile browser tests are temporarily paused in CI because their helpers assume visible multi-edit controls and an open Inspector; repeated waits exhausted the suite timeout. Re-enable them after the helpers handle the mobile disclosure and navigation states reliably. Both browser projects remain available locally through `npm run test:e2e`; use `-- --project=mobile` for mobile only. Official actions are pinned to commit SHAs, the job uses read-only repository permissions and uploads browser reports for seven days.

Inspect visual changes in a real browser at desktop and phone widths. Check map selection, tool panels, viewport expansion and browser errors when changing workspace layout. Pointer-driven mobile emulation does not establish physical touch/pinch correctness.

## Generation and rendering boundary

```js
import { generateWorld, generateDressing } from './src/generation.js';
import { prepareMap } from './src/generation/presentation.js';

const world = generateWorld('the-same-seed');
const dressing = generateDressing(world, 0);
const renderData = prepareMap(world, dressing);
```

These three results are plain data. Run the example from a module at the repository root. `generateWorld` owns geography and feature placement; `generateDressing` owns cosmetic variants; `prepareMap` builds numeric mesh descriptors without mutating the world. Campaign edits are resolved over the generated base by `campaignWorld` and `campaignDressing`.

Use named random streams so changes to one stage do not consume another stage's randomness. Keep seed replay and JSON compatibility deliberate. A change to world-generation rules, vocabulary or naming modifiers requires a generator-version decision and a corresponding snapshot update when applicable. Pure refactors should preserve generated data, dressing and geometry exactly. Cosmetic changes must respect saved dressing snapshots and locks.

Renderer tests in `tests/rendering.test.js` compare seeded mesh buffers, transforms, materials, wind attributes and picking ranges against pre-refactor fixtures in `tests/fixtures/rendering.json`, and verify geometry/material disposal. Treat intentional visual changes as explicit fixture updates; do not regenerate these fixtures merely to make a failing test pass.

The renderer entry coordinates scene lighting and the public `setMap`/`setPalette`/selection/zoom/motion/snapshot/disposal API. `map-meshes.js` owns map geometry and batches props by material/shadow role while retaining face ranges for hex picking. Terrain/river meshes, natural props and crossings have focused builders alongside settlements and POIs. `map-materials.js` owns shared/tinted materials, shader uniforms and depth materials; map rebuilds release geometry while retaining these materials. `map-controls.js` owns the camera, selection rings, picking, pointer/wheel listeners and resize observer. `ambient-motion.js` owns motion scheduling and reduced-motion/visibility listeners. Disposal stops motion and releases controls, map geometry, materials and scene resources through their respective owners. The menu and Inspector share one still preview renderer; avoid adding animated scenes or per-hex WebGL contexts. Inspector previews opt into camera-space fitting of all rendered vertices, including raised tile bases and tall props, with 8% framing padding. Their images fit the square frame at 100% without additional CSS enlargement. Campaign-card icons retain the original fixed framing and thumbnail cache. Three.js is intentionally pinned to `0.160.1`.

`campaign-session.js` owns the active record, base/effective world, dressing, selection and a maximum of 20 undo entries. Actions derive/validate the next state before committing it, then call an injected persistence adapter. Results distinguish world, tracking and palette updates and retain separate campaign/preferences save outcomes. A failed save keeps live changes and history; the DOM handles warnings rather than rolling back an applied action. Palette changes survive hex Undo, and opening/replacing a world resets history.

Party markers store the optional validated `partyToken: { key, style }` record in campaign saves/exports. `application/party-token.js` validates the fixed-footprint key and `cairn`/`warden`/`waystone` style. Campaign entry initializes missing tokens as Warden on the settlement nearest axial origin, with dry-land then any-hex fallbacks, and marks the starting hex visited without an Undo entry. Existing token positions and manually changed visited flags survive entry. Placement commits token position and the destination's existing visited flag together as a tracking action, sharing world/dressing, with one save and one Undo entry. Undo restores the old position and visited state while preserving a later style choice. New Map initializes a fresh token.

`rendering/party-piece.js` builds the three meshes; `party-color.js` preserves the prototype's red/cyan/lime OKLab separation heuristic. `party-token.js` owns the overlay scene, terrain-height placement, marker selection, reduced-motion-aware drop/lean and finite animation scheduling. It uses the map camera without changing it and clears depth before drawing the piece so props cannot obscure it. Preview renderers never create a party controller. Map controls route marker gestures separately from map pan/selection: clicking the piece selects its base highlight only; clicking exposed terrain on its hex still selects that hex. Pointer cancellation and invalid releases return the marker to its saved position. Visited state produces no map marks. Sandbox Tools stays empty; no movement instructions, arrows, style picker or keyboard movement UI is added yet. The style action/data support all three pieces for later UI work.

Multi edit keeps an ephemeral selection set in the session, alongside the primary inspected hex. Opening/replacing a campaign resets the mode; selection changes do not save or enter history. `batch-inspector.js` sends only explicitly chosen fields. `applyBatch` normalizes terrain-dependent removals, merges all target edits through `updateHexes`, derives the final world/dressing once and validates crossings for every target before one commit/save/Undo entry. Shared snapshot invalidation examines the union of affected components before and after the complete batch. Structurally edited locked hexes are relocked with their new dressing; tracking-only batches share the existing world/dressing. Renderer selection highlights are a disposable combined ring mesh; map refresh and silent programmatic selection never toggle batch membership.

`settlement-edits.js` validates connected, same-type town/city selections and assigns a bounded group identity. Join affects exactly the selected tiles, repairs remaining footprints and retains one Undo/save boundary. Village footprints always split into individual cells. Joined records use edit-state version 2 with a validated `settlementGroup`; version-1 records remain accepted. Changing settlement type removes group membership. `map-action.js` uses the menu's two-frame paint delay, busy animation and control disabling for Apply, Join, Select all, Clear selection, Undo, Reset and Regenerate; selection changes are blocked while pending. Selection actions pass their activating buttons through draft protection, so Selecting… and Clearing… paint before highlight geometry is rebuilt. Field errors use a shared red tint and `hexAddress` includes region plus local coordinates.

Ctrl+click or Cmd+click on the campaign map enables multi-edit through the same dirty-draft guard as the mode switch. Cmd+click supports macOS, where Control-click opens the system context menu. The inspected hex stays selected and a different clicked hex is added; clicking that same inspected hex when enabling keeps it selected. Pointer modifiers travel through renderer selection callbacks and deferred draft actions. Further modified clicks toggle membership; an ordinary map click or tap replaces the set with that hex without leaving multi-edit. The coordinate selector explicitly requests additive selection while multi-edit is active. The desktop top toolbar holds the mode switch, which is hidden entirely on mobile. Regenerate sits above Wind on desktop and shares a full-width two-column row with it on mobile, separated from palette options by a divider. New Map and its replacement dialogs are no longer exposed in the campaign workspace. Drag/pinch and creation-preview selection retain their existing behaviour.

Reset selected requires confirmation and removes the selected sparse edit records through null patches in `updateHexes`. Structural removals invalidate affected shared snapshots before rebuilding once. The reset clears selected tracking, locks, local dressing and settlement groups, with one save/Undo entry; seed, palette, global dressing variant and selection remain unchanged. Its confirmation discards selected draft changes directly, without a second draft dialog, and uses the same working indicator as Apply.

The homepage statically imports no renderer or Three.js code. `src/ui/map-view.js` is dynamically imported on campaign entry and shares the still preview renderer with Inspector. Campaign creation/entry immediately disables menu controls, marks the activating button busy and announces loading; feedback paints before synchronous generation or scene work. Errors restore menu controls without discarding saved campaigns. Directional native view transitions run after preparation: left into the workspace, right back to the library. Reduced motion and unsupported browsers switch immediately. Navigation restores menu scroll and focus and cleans up pending transitions on disposal. Failed imports leave the menu usable; reload after a failed module fetch to retry. Keep renderer imports behind this boundary. The browser suite checks requests before/after entry and enforces a 200 KB uncompressed initial-JavaScript budget.

Campaign icons use a stable gallery of up to eight distinct hexes: four settlements followed by four POIs, with remaining landmarks filling shortfalls. Featureless worlds fall back to eligible terrain. After the map paints, still previews are captured one tile per task using the shared renderer. A manually selected Inspector hex is retained as an optional ninth entry, including meadow or water; further manual choices replace that extra entry. Menu refresh cycles only through ready cached entries, wrapping in order. It is disabled until at least two previews are ready, so it cannot select an unseen result. The menu never fetches a renderer.

A best-effort IndexedDB gallery cache and a session fallback each retain at most 32 campaign galleries (up to nine previews each). Each campaign occupies one stable record; new renders replace that record rather than consuming new cache slots. Signatures include campaign identity, cache/generator version, seed, world preferences, variant, palette and visual hex edits; icon choice, names and visited-only changes reuse previews. Cache failures do not affect campaign saves or JSON exports. Palette, dressing and structural edits rebuild stale previews after a short debounce; superseded jobs stop between tiles. The menu retains the last preview of the same hex/world during palette or dressing updates, and reuses card/image nodes to avoid flashing the fallback on navigation. The selected preview is saved before the remaining gallery, so cancellation cannot discard an already rendered cover. A replacement world never reuses the previous seed’s preview. Missing previews use the bundled meadow image, with fixed Dusk ground and Ember foliage. Regenerate that asset with `node tools/render-default-icon.mjs /tmp/wilderness-almanac-default-icon.svg`, then rasterize at 384px with `rsvg-convert`; the tool uses the existing mesh builders and needs no browser or WebGL.

## Campaigns, persistence and links

- `wilderness-almanac:campaigns-v1` stores local campaign records and recoverable deletion state. `hex-sandbox:map-v1` stores the active campaign ID, map preferences, custom palettes and chosen default palette through the storage module. Keep older campaign-field and single-map preference migration support.
- `ui/palette-library.js` owns bundled/custom palette identities and the default; legacy custom palettes gain stable IDs on load. `ui/palette-manager.js` handles the menu dialog, immediate colour/name saves and selection. Clicking the backdrop closes the dialog and returns focus to its opener. Rows use a roving focus with arrow-key wraparound and Home/End navigation; Enter edits a custom name, while input fields retain their native arrow-key behaviour. Each row places its name and default label before right-aligned colour hexes, with shared separators and a full-row selected state. Pointer hover lightens the row background while retaining its selection marker. Bundled entries are read-only, custom entries can be deleted without confirmation, and deleting the custom default restores Forbidden Lands. The campaign menu resolves the current default when creating each campaign. Library changes refresh the campaign selector without altering existing campaign colours or replay records; the menu keeps its lazy renderer boundary.
- `ui/campaign-creator.js` owns the unsaved New campaign dialog and its preview renderer. Opening the dialog lazily loads `map-view.js`; the idle menu still avoids renderer imports. The draft uses version-8 generation with four validated five-step world preferences. `generation/settlement-placement.js` owns version-8 regional plans, land budgets and site eligibility. `generation/world-preferences.js` owns their normalized schema and additive name-weight composition; the focused generation stages consume them. See [WORLD_PREFERENCES.md](WORLD_PREFERENCES.md) for probabilities, percentage targets, interactions and replay contracts. The preview starts at its default view once per dialog opening; subsequent generations retain the user’s pan and zoom, without reapplying the initial zoom multiplier. Seed/slider edits require Generate before Create; Keep current map returns to the last generated seed/preferences without rendering again. Names and palette choices do not require generation, and edited names survive regeneration. Closing, Escape or a backdrop click confirms changed drafts, and canceling a draft does not add a campaign. The footer Close button is hidden at the mobile workspace breakpoint; the title-bar close control and guarded backdrop dismissal remain available. Preview resources are disposed on close and before entering a campaign, with revision guards for canceled lazy loads. Generated preferences are saved with the campaign; Keep current map restores the preview settings exactly.
- Campaign records carry identity, creation time, editable-name state, generator version, seed, normalized world preferences, dressing variant, three palette seeds/name and icon hex. Versions 6/7 retain their original replay; version 8 adds regional settlement planning, rare slope villages and POI preference refinements. The session replacement API can replace that record's world while preserving identity, creation time and palette; the workspace no longer exposes a replacement control. A name follows the generated map name until explicitly renamed.
- Export envelope version 2 includes sparse hex edits (version 1, or version 2 for joined settlements) and bounded frozen dressing descriptors. Version-1 envelopes still import. Older apps reject version-2 edit state rather than silently dropping joined footprints. Validate dates, lengths, coordinates, enums, finite dimensions and prop limits; reject unsupported generator versions and imports over 4 MB. Never accept arbitrary mesh data from imports.
- Downloads use a filename-safe campaign name and local date: `wilderness-almanac-[campaignname]-[YYYY-MM-DD].json`. Import adds a separate local campaign. The palette travels with that campaign; the full custom-palette library does not.
- Map links contain `seed`, `variant`, three colour seeds, `generator` and the four ordered `world` preference steps, with URL values taking precedence over local preferences. Unversioned links retain version-6 replay. They omit hex edits, visited status and locks. Changing the map updates the URL without adding browser-history entries.
- `campaign-store.js` owns campaign-library reads/writes. Retain unreadable campaign records verbatim alongside editable records, preserving unknown envelope and local campaign fields without feeding them into rendering. Unknown/malformed library envelopes and unreadable deletion records are read-only. Do not treat failed reads as an empty/first-run library or overwrite them during preference migration.
- Check the stored library against the loaded snapshot before writing. A detected change from another tab blocks that write; users can download their current in-memory campaigns before reloading. This is a best-effort conflict check, not a transactional cross-tab lock.
- `save-status.js` tracks campaign and preference failures independently of action-console messages. Clear each failure only after that storage target writes successfully. Persistent warnings remain in the menu/map through other actions, and the map offers a direct campaign download.
- Recovery downloads preserve this tab's last read or successfully written library text, including unreadable records. They are separate from ordinary campaign exports and are not accepted by the single-campaign import flow.
- Handle blocked/full browser storage without losing the active in-memory session. Storage capacity and the import-size limit are independent.

Deletion requires confirmation. Undo deletion expires on the next campaign action, including entering, renaming, icon changes, copying/sharing, exporting, creating or importing. Initial tile icons choose the first prepared landmark. Refresh cycles the cached gallery; Inspector icon selection persists independently of hex Undo history and expires deletion Undo like other campaign actions.

## Interface conventions

Styles follow CUBE CSS in ordered `reset`, `tokens`, `base`, `compositions`, `utilities`, `blocks` and `exceptions` layers. Use native nesting within blocks, `cluster`/`stack`/`grid-pair` for composition, and shared rem-based spacing, typography and control tokens. Keep state overrides in `exceptions`; reserve `!important` for the native `hidden` contract. Prefer labelled semantic HTML and remove wrappers when the parent can own the layout. Keep reusable UI structure in native `<template>` elements in `index.html`; clone with `src/ui/templates.js`, then populate text, attributes and options through DOM APIs. Preserve static icons when updating labels.

Use Geist Sans for body copy and controls, and Geist Pixel Square for titles, metadata values, seeds and status details. Fonts are local and preloaded. Keep the render-blocking stylesheet and inline dark defaults in `index.html` so the initial paint does not flash white or unstyled content.

The campaign library retains its original dusk-and-gold theme with the initial Forbidden Lands default. Choosing another default derives menu surfaces, text, borders, focus and heading accents with the same `paletteTheme` function as the campaign UI. Changes apply immediately, including edits to a custom default, and restore the original theme when Forbidden Lands becomes default again. The page background is scoped to the visible menu; campaign controls follow their own saved palette. Keep one shared 2px corner radius, a 4/8/12/16/24/32px spacing scale, 12px control and metadata labels, 40px desktop controls and 44px touch targets; compact icon controls retain their established target sizes. Buttons share a 5% press scale; reduced motion disables scaling and transitions. Page transitions use the two locally copied Open Props circular-in/out easing tokens for exit/entry in either direction. Use only the needed Pixelarticons paths in the local SVG sprite and retain its source/license notes.

The workspace root is `#campaign-workspace`. Desktop places the map left and tools right; panels can reorder, minimise vertically or fold into rails. Mobile reserves room within the initial viewport for the collapsed Inspector and Sandbox tools headers below the map. Both panels reset to collapsed on campaign entry and when entering the mobile breakpoint, expanding only through user action. Their transient mobile state is separate from saved desktop collapse/rail preferences. The mobile top bar keeps its title and back control; seed/copy/share controls move into expanded palette settings. Mobile palette settings omit the duplicate Return to menu action in both disclosure states. The palette and coordinate selectors reserve the same trailing column and gap, aligning their right edges whether settings are open or closed. Their disclosure control shares the Regenerate/Wind row on the right and uses the same compact button and icon sizing as the tool panels. The Sandbox tools panel retains the internal `tracker` preference key for existing saved layouts. Expansion fills the browser viewport using CSS, with browser chrome retained. Preserve settings and desktop panel preferences across campaigns and screen sizes.

Wind controls share accessible switch/diode semantics with visited status. Respect reduced-motion preferences, pause animation in hidden documents, and keep transient action announcements separate from silent hover-coordinate updates.
